Judge Checklist

Quick ways to verify this is enforcing business constraints, handling conflicts, and isolating failures.

How to run the demo
  1. Click Open Google Sheet.
  2. (Optional) Do one “Try this” change below.
  3. Enter your email and click Run Autonomous Dispatch Audit.
  4. Wait ~60–90 seconds, then check the Sheet + your inbox.
1) Dynamic Operating Policies (no hardcoded hours)

What it proves: Operating bounds are read from the Operating_Policy tab (Operating_Day_Start, Operating_Day_End) rather than being hardcoded.

Try this: Change Operating_Day_End from 22:00 to 14:00, then run an audit.

Expected: Proposed schedules respect the updated operating window (business constraints enforced by the sheet).

2) Calendar Deconfliction + Partial-Shift Fallback

What it proves: Overlapping shifts at the same location are deconflicted, and if a full shift is unsafe, the engine can fall back to a safe partial-window plan.

Try this: In Audit_Queue, include sample rows with overlapping times at the same location, plus a longer shift that hits peak heat (e.g. spanning 12:00–16:00).

Expected: Conflicts avoided + proposed safer windows, including partial shifts when no full safe block exists.

3) Error Architecture (failure isolation)

What it proves: Operator-facing summaries and engineering incident alerts are separated.

Expected: The executive summary is delivered to the requesting operator (the email you enter). If a pipeline crash occurs (external API outage or schema corruption), an asynchronous incident alert is routed to operations engineering via the dedicated Error Trigger workflow.
